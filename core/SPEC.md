# Devour Sphere (コアプログラム)

ここではシューティングゲーム「Devour Sphere」のコアプログラムについて説明する。

## コンセプト

プレイヤーはサイバー空間の中に生まれた「生命体」。
その空間ではプレイヤーと同じような生命体が球状の物体「プラネット」の
表面付近に集まって弱肉強食の生態系を形成している。
生命体は、自分と近い大きさ (自分の 2/3～1.5倍) の大きさの他の個体を攻撃できる。
攻撃を受けた生命体は「体力」を奪われ、体力がゼロになると死ぬ。
死んだ生命体は自身を構成したいた「部品」をばらまき、それが他の生命体の餌となる。
餌を食べることで生命体は大きく成長し、より大きな他の個体を攻撃可能になる。
プレイヤーは他の生命体と戦って部品を集めてより巨大化し、
今いるプラネットで最も巨大な生命体となることを目指す。

このゲームは「slither.io」から着想を得ている。

## 部品

生命体の構成要素。
部品には大きさがある。大きさは 1、2、4、8、... と 2 のべき乗の値をとる。
画面上では大きさに比例して「青緑色の正方形の 1 つの頂点を長く引き延ばした盾のような形」として描かれる。

## エネルギー粒子

生命体が攻撃を受けることで奪われた体力はエネルギー粒子となって浮遊する。
画面上では星のような「白い光の点」として描かれる。

## 生命体

部品が集まって意思を持つようになった存在。
プレイヤーも他の生命体と同じ存在であるが、その形状は個体によって異なる。
浮遊している部品に触れて取り込むことでその分巨大化する。
体力ゲージを持ち、生まれた時は満タンだが、攻撃を受けることで体力が減る。
体力はエネルギー粒子に触れて取り込むことで回復する。
体力がゼロになると生命体は死に、部品がバラバラになって浮遊する。
生命体同士が衝突した場合、大きい方が小さい方を取り込む。

### コア

生命体の意識を司り、部品を一つの塊に繋ぎ止める中核。
生命体が死ぬとコアは消滅する。
画面上では白い部品として描かれる。

### 生命体の描画

部品の集まりとして描画する。

生命体は X, Y の 2 次元のローカル座標系を持ち、その中でコアと部品が配置される。
生命体の進行方向を Y 軸、生命体の右方向を X 軸とする。
コアは原点より前方よりに固定されており、尖った頂点を前方に向けている (戦闘機のコックピットのイメージ)。
コアのやや後方に部品が横に広く寄り集まっている (戦闘機の翼のイメージ)。
コアの大きさは生命体自身の大きさ (部品の大きさの合計) に比例し、位置も大きさに比例して前進する (翼に埋もれないように)。

部品の配置は次のように決定する。

- 全ての部品は X 軸の正の方向にだけ存在するが、個々の部品の「分身」が Y 軸を境に反転した位置に存在する。
- コア、部品、部品の分身を含めた全体として生命体は左右対称の見た目になる。
- 体内のコアと部品は、互いの距離の 2 乗に反比例して引力が働き、距離の 3 乗に反比例して斥力が働く。
- 部品の位置はリアルタイムで計算され、浮遊している部品が取り込まれて体内に入ることで有機的に形が変化していく。
- 描画するときは X 軸の位置をやや大きくとり、翼のように横長に広がって見えるようにする。

これにより、コアのやや後方に左右対称に部品が寄り集まった、鳥や飛行機のような形状になる。

個々の部品の向きは、生命体のやや前方もしくはコアを中心として部品の尖った頂点をその反対方向に向けて放射状に配置する。
部品の尖った頂点が後方に向かって開くように配置されるので、より翼っぽくなる。

### 大きな部品の合成

体内で同じ大きさ同士の部品が十分近くまで接近すると合体し、2 倍の大きさの部品となる。

### 他の生命体への攻撃

体力を少しずつ消費して他の生命体を遠距離攻撃できる。
プレイヤーはゲーム開始時に武器を選ぶ。

- バルカン砲: 縦スクロールシューティングゲームのバルカン砲のような弾。威力が小さく弾速も遅いが連射が速く、接近戦に有利。遠くに行くほど広く広がる。
- レーザー: 細長い弾。当たる範囲は狭いが弾速が速く、威力が強い。
- ミサイル: 敵を追尾する弾。自動で近くの敵を追尾するが、威力は弱い。

弾は生命体の大きさに応じて大きく強力になるが、弾速は変わらない。
自分の弾はオレンジで、敵の弾はピンクがかった赤で描かれる。

レベルの低いプラネットでは敵は攻撃してこない。
レベルが上がるにつれてバルカン、ミサイル、レーザーなどを使う敵が現れてくるようになる。

## プラネット

生命体が集まる仮想の星。
プラネット上には最大 1024 個の部品と 256 体の生命体が存在できる。
生命体はプラネットの地表から少し離れた空中を地面と平行に移動する。
それぞれの生命体の位置と進行方向は 3 次元ベクトルで表される。
小さな生命体はより高い位置に、大きな生命体はより低い位置を飛んでいる。
プレイヤーが小さいうちはまだ交戦できない大きな生命体を下に見下ろす形になる。
プレイヤーが交戦可能な敵は本来の色で、交戦できない敵は灰色に描かれる。
プラネット自体はイコソスフィアのワイヤーフレームのように描かれる。
プレイヤーがプラネットに降り立った時点ではさまざまな大きさの生命体が
プラネット上を回遊しており、プレイヤーはその中でかなり小さい方の存在。

プレイヤーがプラネットで最も大きな存在になると
そのプラネットから飛び立ち、新たなプラネットを目指す。
プレイヤーの大きさは画面上では維持されるが、
ゲーム内部ではプレイヤーを小さな存在に戻すことで
より巨大なプラネットに進出したように見える。
(内部で数値が際限なく大きくなってオーバーフローすることを防ぐ意味もある)

## 操作

何も押さなくても前方へ巡航する。
左右キーで左右に旋回。
上キーを押している間体力を消費しながら高速で前進する (ダッシュ)。
下キーを押している間減速し、最終的に停止 (ブレーキ)。
ブレーキを押しながら旋回することでクイックターンができる。
A ボタンで攻撃。押したままで連射。

PC では ↑↓←→ と WASD を方向キーとして使う。
IJKL キーとスペースバーを A ボタンに割り当てる。

## 画面配置

プレイヤーの後方上をカメラがついていく三人称視点。
プレイヤーが左右に旋回するとカメラはやや左右にロールする。
自分の体力ゲージと、今いるプラネット内での自分の大きさの順位が画面隅に表示される。
ダッシュ時はカメラがプレイヤーの後方に近づき、ズームして視界が狭くなる。
ブレーキ時はカメラがやや引いて広角になり、遠くを見渡せる。

## デザイン

黒い背景にワイヤーフレームのプラネット、その上空を単色で原色の生命体や部品が浮遊するサイバネティックな見た目。

## 実装

実装は C++ を使う。
コアプログラムは特定のプラットフォームに依存しないが、組み込み機器で実行することを想定し、
例えば計算量の多い部分は固定小数点化するなどの工夫をする。
描画周りは ShapoGFX (submodule/shapo-gfx/) を使う想定。

include/devoursphere にはアプリケーション実装側へ公開するヘッダファイルが置かれる。
src/ にはコアプログラムの実装が置かれる。

## 実装仕様

ここから下は上記の設計を実装した際の取り決めをまとめたもの。
数値の既定値は core/include/devoursphere/sim/config.hpp にあり、そちらが正。

### 構成

コアプログラムは 2 つのライブラリに分かれる。

| ライブラリ | ディレクトリ | 依存 | 内容 |
|---|---|---|---|
| `devoursphere::sim` | include/devoursphere/sim, src/sim | なし | ルール、物理、AI。整数演算のみ |
| `devoursphere::render` | include/devoursphere/render, src/render | sim, ShapoGFX | 状態を Surface に描く |

`sim` は浮動小数点を一切使わない。同じシードと同じ入力列を与えれば
WASM、ネイティブ、RP2350 のどれでもビット単位で同じ状態になる (テストで検証している)。
`render` は float を使うが、描画結果がプラットフォームで多少違っても構わない。

```
include/devoursphere/
  devoursphere.hpp        まとめてインクルードするヘッダ
  sim/fixed.hpp           固定小数点、三角関数、整数平方根、ベクトル、乱数
  sim/config.hpp          定数 (スケール、上限、速度、武器、AI)
  sim/entities.hpp        Creature, Part, FloatingPart, Bullet, Particle, Button
  sim/game.hpp            Game: 状態機械と tick()
  render/renderer.hpp     Renderer: beginFrame() / renderBand() / endFrame()
src/sim/                  fixed.cpp entities.cpp game.cpp creature.cpp combat.cpp
src/render/               renderer.cpp planet.cpp hud.cpp
test/                     sim_test.cpp (ctest), sim_bench.cpp (バランス・負荷計測)
tools/gen_tables.py       sin テーブル (src/sim/sin_table.inc) の生成
```

### 数値表現

- **Q30**: int32 で 1.0 = 2^30。単位ベクトル、三角関数、比率に使う。
  積は int64 で計算して 30 ビット右シフトする。
- **brad**: uint16 の角度。65536 = 1 周。sin/cos は 1025 点の 1/4 周テーブルと線形補間。
  atan2 は多項式近似 (誤差 0.1 度未満)。
- **units**: int32 の長さ。`PU = 256 units` を「部品単位」と呼び、大きさ 1 の部品の幅に相当する。
- プラネット半径 `R = 2^17 units = 512 PU`。2 のべき乗なので
  「単位法線ベクトルの差 (Q30) を 13 ビット右シフトすると units の弦長」になり、
  近傍判定を除算なしで行える (`tangentialDist2()`)。
- 整数平方根は「初期値を上から与えたニュートン法」で、32 ビット除算だけを使う。
- 乱数は xorshift32。プラネットごとのシードは `Game::planetSeed()`。

### 時間と入力

- 30 tick/秒固定。`Game::tick(buttons)` を呼ぶごとに 1 tick 進む。
- 入力は 5 ビット: LEFT, RIGHT, UP (ダッシュ), DOWN (ブレーキ), A (攻撃・決定)。
- 描画は tick と独立に何度呼んでもよい (状態を変えない)。

### 位置と姿勢

生命体、弾、部品、粒子はすべて「単位法線 n (Q30) と中心からの距離 r (units)」で位置を持つ。
生命体と弾はさらに進行方向の単位接ベクトル t を持ち、右方向は `t x n`。
移動は `n' = normalize(n + t * speed / r)`、その後 t を n' に直交化する。
旋回は t を n の周りに回転する。

高度 (r - R) は大きさで決まり、小さいほど高い:

```
altitude(size) = ALT_MIN + (halfSize(14) - halfSize(log2 size)) * ALT_FACTOR
halfSize(k)    = (PU / 2) * sqrt(2)^k       (大きさ 2^k の部品の凧の半径)
```

大きさが 2 倍になるごとに間隔が広がるので、巨大な個体同士の階層が重ならない。
高度は毎 tick 目標値に 1/32 ずつ近づく。

### 生命体

- `size` は部品の大きさの合計で、これが正。部品の一覧はその視覚的な分解であり、
  部品数の上限 (16) に達したときは最小の 2 個を強制合体させるため合計は size と一致しないことがある。
- 体力 `hpMax = 32 * size`。部品を取り込むと hpMax が増え、hp は比率を保つ。
  自然回復はなく、エネルギー粒子を取り込んだときだけ回復する。
- 巡航速度 `SPEED_BASE + SPEED_PER_LOG2 * log2(size)` (units/tick)。ダッシュは 2.25 倍
  (体力は消費しない)。ブレーキは速度を 0 に向けて減衰させ、旋回速度が 2 倍になる。
- 旋回は 3 度/tick (ブレーキ中 6 度、ダッシュ中 2 度)。
- 攻撃可能: `2/3 <= 相手 / 自分 <= 3/2` (`canAttack()`)。

部品の配置 (ローカル座標、units):

- コアは `(0, coreY)` に固定。`coreHalf = halfSize(log2 size) * 5/8`、`coreY = coreHalf * 3/2`。
- 部品は `x >= halfSize/4` の右半平面に置き、`(-x, y)` に分身があるものとして力を計算する。
- 力は「平衡距離 d0 = (半径の和) * 9/8」を境に、`F = A * (d0/d)^2 * (1 - d0/d)` で
  遠くでは 1/d^2 の引力、近くでは 1/d^3 の斥力になる (A = 半径/4、-4A..A にクランプ、
  遠方では最低 A/8 の引力)。相手はコア、他の部品、全部品の分身 (自分の分身を含む)。
- さらに「コアの後方の休止線」への弱いばね (±A/2) で翼が後ろに広がる。
- 速度は毎 tick 1/2 に減衰し (強い減衰で揺れが残らない)、大きさは半径/4 に制限する。
  十分小さくなった速度は 0 にして静止させる。
- 同じ大きさの部品が半径の 5/8 より近づくと合体する (1 tick に 1 組)。
- プレイヤーから 90 PU 以内の個体は毎 tick、それより遠い個体は 4 tick に 1 回更新する。
- `bodyRadius` は部品の広がりから求め、捕食や被弾の判定半径に使う。

描画側は部品の位置を x 方向に 1.4 倍して翼のように広げ、
尖った頂点を「コアのやや前方の焦点 (`layoutFocusY`)」から遠ざかる方向に向ける。

### 武器

| 武器 | 弾速 (PU/tick) | 寿命 (tick) | 間隔 (tick) | 威力 (× size / 8) | 同サイズを倒す弾数 | 拡散 | 誘導 |
|---|---|---|---|---|---|---|---|
| バルカン | 2.5 | 45 | 4 | 32 | 8 | ±5 度 | なし |
| レーザー | 8 | 28 | 14 | 128 | 2 | なし | なし |
| ミサイル | 1.75 | 100 | 12 | 56 | 5 | ±20 度 | 4 度/tick |

- 発射ごとに hpMax を 2^n で割った体力を消費し、体力が 1/16 以下だと撃てない。
- 弾は発射時の持ち主の大きさを記憶し、その大きさから見て攻撃可能な相手にだけ当たる。
  判定は接線方向の距離 < `bodyRadius + 弾半径`。
- 与えたダメージはエネルギー粒子になって体の外へ飛び出す。粒子は 2 秒間は取り込めない
  (撃たれた本人がすぐ回収できないようにするため)。寿命 12 秒。

### 捕食と吸収

- 浮遊部品は `bodyRadius + 部品半径` 以内で取り込む。ただし自分の 1/32 未満の部品は無視する
  (巨大な個体が小さな餌を掃除してしまわないように)。
- 生命体同士の衝突は攻撃可能な範囲 (2/3～3/2 倍) にある相手とだけ起きる。
  小さい方のコアが大きい方の体 (bodyRadius の 3/4) に入ると大きい方が吸収する。
  攻撃できない巨大な相手にいきなり吸収されることはない。
- 部品や生命体を取り込んだ直後の 1 秒間は吸収されない (`absorbGuard`)。
  成長して新たに交戦可能になった隣の個体に即座に吸収されるのを防ぐ。
  出現直後の無敵時間 (`invincible`) は被弾と吸収の両方を防ぐ。
- 死んだ生命体は部品 (と分身) を浮遊部品としてばらまく。ばらまかれた部品は
  「自分の 4 倍の大きさの生命体の高度」へゆっくり移動し、同じ階層の個体の餌になる。

### プラネット

- 生命体 200 体で開始し、減ると 0.5 秒ごとに小さな個体が補充される。
  大きさの指数は `min(2 回の一様乱数)` で小さい個体ほど多い。上限は `8 + レベル` (最大 16)。
  最初の 3 体は上限の大きさで生成する。
- 「餌」として浮遊部品 (大きさ 1～8) を 320 個ばらまき、400 個を下回る間は 4 tick ごとに補充する。
- レベルによる敵の振る舞い:
  - 1: 攻撃してこない (餌を追うだけ)
  - 2: バルカンで攻撃する
  - 3: バルカンとミサイル。ダッシュも使う
  - 4 以上: レーザーも使う
- プレイヤーの順位が 1 位になって 4 秒経つと LAUNCH 状態 (3 秒間上昇) になり、
  次のプラネットへ移る。プレイヤーの部品の指数を `log2(size) - 3` だけ下げて
  内部的に小さく戻し、下げた分を `playerDisplayScaleLog2()` に積算する (HUD の表示用)。

### 状態機械

```
TITLE  --A-->  WEAPON_SELECT  --A-->  PLAYING  --順位 1 位-->  LAUNCH  -->  PLAYING (次のレベル)
                                         |
                                         +--死亡-->  DEAD  --A (2 秒後)-->  TITLE (新しいシード)
```

TITLE と WEAPON_SELECT の間はプレイヤーを AI が操作し、アトラクトモードになる。

### AI

8 tick ごと (個体ごとにずらす) に判断する。

1. 脅威: 攻撃可能で自分より 1.25 倍以上大きい個体 (レベル 2 以上)、または攻撃範囲外の
   大きな個体が 40 PU 以内にいれば逃げる (レベル 3 以上では近ければダッシュ)。
2. 餌: 視界 (120 PU) 内の最寄りの浮遊部品へ向かう。
3. 獲物: 攻撃可能で自分以下の大きさの個体へ向かい、前方 15 度、射程内で撃つ
   (レベル 2 以上。プレイヤーを AI が操作するときはレベルによらず撃つ)。
4. それ以外はゆっくり向きを変えながら巡航する。

### 近傍探索

生命体、浮遊部品、粒子はそれぞれ「n.z でソートした添字配列」を毎 tick 保つ
(前 tick の順序を引き継いで挿入ソート)。距離 d 以内の候補は z の帯
`|Δz| <= d << 13` の二分探索で絞る。衝突、捕食、被弾、AI の視界がこれを使う。

### 描画 (render)

- 座標系はプレイヤー位置を原点とする float の PU。精度を保つため、
  すべての位置は整数 units で差をとってから float に変換する。
- 1 フレームは `beginFrame()` で組み立て、`renderBand(dst, y, h, dstY)` で
  行範囲を描き、`endFrame()` で閉じる。帯は何度呼んでもよいので、
  フレームバッファを持てない機器では帯単位で転送できる。
- 描画順: 背景 (黒) → 星 → エネルギー粒子 (点) → プラネットのワイヤーフレーム (線) →
  3D パス (ShapoGFX Graphics3D、クリア無効で重ねる) → HUD。
- プラネットは正二十面体を再帰分割して描く。地平線の向こう側の面と
  カメラの後ろの面は捨て、画面上の辺の長さが 56px を超える面を最大 7 段まで分割する。
  隣接面で共有される辺はハッシュ表で重複を除く。線は距離に応じて暗くする。
- 生命体はコアと部品 (と分身) を凧型 4 頂点 (2 三角形) の平面ポリゴンとして投入する。
  距離順に並べ、三角形バッファの 3/4 を予算として近い個体から全部品を描き、
  予算を超えた個体や画面上で小さい個体は 1 枚の凧に落とす。さらに小さいものは点。
  色はプレイヤーが青緑 (浮遊部品と同じ)、交戦可能でプレイヤーより大きい敵がピンク、
  交戦可能でそれ以下の敵が水色、交戦できない個体は灰色。出現直後の無敵時間中は点滅。
  交戦可能な敵の上には体力ゲージを描く (3D パスの後、HUD の前)。
- 弾は加算ブレンドの小さな凧 (バルカン、ミサイル) と細長い四角形 (レーザー)。
  自分の弾はオレンジ、敵の弾はピンクがかった赤。
- カメラは後方上空の三人称で、およそ 45 度の俯角で見下ろす。距離は `3.5 * bodyRadius + 8 PU`
  (最低 11 PU)、高さは距離と同じ。ダッシュで近づいて視野 58 度、ブレーキで引いて視野 82 度、通常 70 度。
  旋回で最大 9 度 (ブレーキ中 14 度) ロールする。値は指数関数的に補間する。
  タイトルではプレイヤーの周りを回る。
- HUD: 体力ゲージ、順位、大きさ (プラネット遷移で縮めた分は `x2^n` で併記)、
  プラネットのレベル、武器名。被弾時は画面の縁が赤く光る。

### メモリ

| 対象 | サイズ |
|---|---|
| `sim::Game` | 約 185KB (生命体 256 x 416B、浮遊部品 1024 x 40B、弾 256 x 56B、粒子 512 x 44B) |
| `render::Renderer` | 約 60KB (線分 3072、点 768、辺のハッシュ表 16KB) |
| 3D アリーナ | 128～192KB (三角形 1 個 約 160B) |

いずれも動的確保をしない。RP2350 (520KB SRAM) では帯バッファを含めて
収まるようにアリーナと上限を調整する必要がある。

### テスト

`core/test/sim_test.cpp` (ctest) は固定小数点演算の精度、決定性 (同じ入力列で
状態ハッシュが一致)、数千 tick 後の不変条件 (部品数と大きさの範囲、単位ベクトルの長さ、
高度が地表より上)、メニュー遷移、死亡、プラネット遷移を検査する。
`-DDEVOURSPHERE_SANITIZE=ON` で ASan/UBSan 付きでビルドできる。
`sim_bench` は AI にプレイヤーを操作させてバランスと tick の処理時間を表示する。
